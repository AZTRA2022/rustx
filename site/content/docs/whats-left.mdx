The repository keeps two logs: `docs/manques-du-framework.md` — what is missing and what is broken, written while building a real application on top of it — and `docs/chasse-aux-bugs.md` — what a project written **from the outside** broke, and what repaired it. This page gives their state.

The method is the same in both: `rustx new` in a neighboring folder, the libraries installed by the commands given in their own getting-started pages, no workaround, no version chosen to get the build through. The project points at the repository's sources, so each fix is verified within seconds.

## The state of the logs

The **50** entries of the bug hunt are closed. Of the **46**
entries of the log of gaps, two are genuinely open, two are
half-closed, and two are sentences that the compiler states rather
than silences.

## What is still open

- **An `async fn` written beside a page cannot reach a value of the page.** The compiler refuses this explicitly, and says where to declare the value. A page reads its values in an `async` block written *inside* the component, and an ordinary `async fn` takes what it needs as arguments. This is a limit, not a surprise.
- **A component `.await` that borrows a local** does not compile: the future leaves for the runtime, and a borrow from the thread that draws does not follow it. This is ordinary Rust, and the way out is to take the arguments by value — but the message comes from `rustc` and points at a column of a generated file that the developer has never opened. Documented, not refused.
- **Installer panels and software metadata per OS.** Nothing yet writes, for an application built with `rustx`, what a Windows installer, a macOS `.app` bundle or a Linux `.deb`/`.rpm` shows before it opens: display name, author, version, the icon in each system's own format. Not started.
- **Completion and auto-import for an installed crate's own functions and components inside a `.rsx`.** `rustx-lsp` already relays `rust-analyzer` for the generated file; what a `.rsx` cannot yet do is list a crate's public items before the full path (`rustx::dialog::open`, `std::fs::read`) is typed out by hand, the way the Rust Analyzer extension does for ordinary `.rs` files. What exists today (`libraries.rs`, `suggest.rs`) covers the JavaScript libraries declared in `package.json`, not Rust crates.
- **Half-closed: a component name that collides with a library's.** `LineChart` written without its library's name can resolve to the wrong one if two installed libraries both export something by that name — `recharts` and `lucide-react` both do. The silent failure this used to cause is fixed (see below); the collision itself is not yet flagged at build time.
- **Half-closed: global shortcuts, the tray and window control on Linux and macOS.** The clipboard, notifications, autostart, a single instance, the camera list, and the file dialog are now real on both; these three still need a desktop portal over D-Bus (Linux) or `AppKit`/Carbon (macOS), which is a live attachment rather than a program to shell out to. See [What is not written](#what-is-not-written).

## What is not written

These are not defects: they are things that no application has yet demanded hard enough to decide their shape.

- **Global shortcuts, the tray and window control, on Linux and macOS.** Everything else — the clipboard, notifications, autostart, a single instance, the camera list, and now the file dialog — is real on both, each by a program or a file the system already ships (`xclip`/`wl-copy`, `notify-send`, a `.desktop` file, `zenity`/`kdialog`, `pbcopy`/`pbpaste`, `osascript`, a `LaunchAgent` plist, a Unix socket, `/sys/class/video4linux`, `system_profiler`) rather than a library this crate would have to add. These three still need either a desktop portal over D-Bus (Linux) or `AppKit`/Carbon (macOS) — a live, in-process attachment rather than a command to run — and refuse by naming the platform and the feature. The Linux files are verified with `cargo check --target x86_64-unknown-linux-gnu`, which this machine can run without a Linux machine to run the result on; the macOS files have only been read over by hand, since no Apple target is installed here at all.
- **Dragging a whole title bar.** An event does not yet say **what** was pressed, so the handle of `window::drag()` sits on an empty space and not on the entire `<header>`, which would swallow the clicks on its own buttons.
- **Dragging a file *out of* the application** to the explorer.
  The other direction works and gives the real paths; this one requires an object that the window's process must hold for the whole gesture.
- **Closing to the system tray.** The icon does not keep the application alive: the message loop stops with the last window. The "minimize to the tray" behavior requires keeping a hidden window, and that is not written.
- **Recording and capture** beyond what Chromium already gives — `MediaRecorder`, `getDisplayMedia`.
- **A theme written by the framework.** `rustx new` could write the complete style sheet, which would make the framework the author of a theme. This is a choice to make, not an oversight; in the meantime, the minimal block is [documented](/docs/javascript-libraries/tailwind) where Tailwind is installed.

## What the logs have closed

For those who want to know what the two nights of bug hunting changed.

**The router** was measured against Next's, and what it lacked was written: the *query string*, the catch-all `[...path]`, the route groups `(section)`, `forward` and `replace`, the parameters of a `Layout`, `loading.rsx` and `error.rsx` per segment, and a readable history stack.

**The JavaScript boundary**: an `Element` can be a child of a library component, `Event` carries the value, the key, the target and the modifiers — including on a tag written inside a React subtree — `Value` has its accessors, and a callback receives all of its arguments.

**The compiler**: a dozen rewrites that emitted wrong Rust, each with the test that had found it. And the comments of the markup, which were shown on screen: the three forms — `//` at the start of a line, `/* … */`, and `{/* … */}` — are read and discarded, between the children as between the attributes; `see https://example.com` stays a sentence, and that is a law.

**The window**: `toggle_maximize()` and `toggle_fullscreen()`, because a title bar does not have two buttons but one that toggles; the place from before full screen retained and restored; and the **seven pixels** that Windows painted above a frameless window, taken back by `WM_NCCALCSIZE` without losing the resize edges.

**What a style sheet must carry.** This one was not in the framework, and it was worse: nothing complained. `--background` declared without `@theme inline` makes `bg-background` a word in an attribute, and the window opens white. This is said where Tailwind is chosen, and three laws measure it in the window: the background color, the text color, and the effective font.

**Linux and macOS got five capabilities each, by the same idea applied twice.** `rustx-os` already shelled out to `xclip`/`notify-send` for two of Linux's capabilities; this extended that to the clipboard, notifications, autostart, a single instance, the camera list and the file dialog on both platforms, each by a program or a file the system already ships rather than a library this crate would have to add — a `.desktop` file and a `LaunchAgent` plist for autostart, a Unix domain socket for a single instance (the one piece both platforms share verbatim, being both Unix underneath), `/sys/class/video4linux` and `system_profiler` for the camera list, `zenity`/`kdialog` and `osascript` for the file dialog. The Linux files are checked against the real `x86_64-unknown-linux-gnu` target; the macOS ones, with no Apple target available to check against at all, are read over by hand only.

**What a night of actually running the stress-test application found.** A comment written on the line before a write to a page value cancelled that write — the code that decides whether what follows is a statement or an operator only looked back over whitespace, not over a `//` or a `/* … */` in the way. `style="width: 50%"` crossed the boundary to a library component as a string, and React refused it outright (error #62); it is translated into an object now. A component name that collided with an installed library's own (`LineChart` resolving to an icon library rather than to `recharts`) used to take the whole screen down without a word — React error #130 — and now says which component threw and why. `router::replace` called from an `async` block did nothing, because the router lived in thread-local storage and a future does not always run on the thread that opened the page; it is shared by the whole process now. `rustx dev` rebuilt the project forever, because every generated file got a new timestamp on every build even unchanged; every write the compiler makes now compares content first. A window left open in one project could make the other fail to build at all (`Access is denied`, `os error 5`) because both share a CEF binary that gets deleted and recopied on every build; this is now caught and named before cargo runs. `rustx new` asked for `rustx = "0.1"`, which cargo's own rule for 0.x versions does not satisfy once the framework reaches 0.2 — new projects were silently getting the version from before. And two reported directly against the stress-test application: `rustx new` left nothing for the first `npm install` to write into, and a `rust-analyzer` that died mid-session left this language server mute for the rest of it; both write a file or restart a process that they previously left for the developer to notice and fix by hand.
