## What a version says

The workspace is at `0.5.0`, in `[workspace.package]` of the repository's
`Cargo.toml`, in one place for all eight packages. A `0.x` version says that
the API may still move. `1.0.0` will say that it will not. What remains to be
written (macOS, Linux, media, parts of async) will still touch signatures before
then.

Cargo treats a change of the **minor** number before 1.0 as a breaking change.
A dependency written `0.3` accepts `0.3.x` and does not select `0.4.0`.

## Moving a project

Three things move: the command-line tool, the library your project depends
on, and the editor tools.

**The library.** Change the version in the project's `Cargo.toml`:

```toml
rustx = { package = "rustx-app", version = "0.5" }
```

Then build. `rustx new` writes this line; if the number in your project is
older than the release you want, this is the only place to change it.

**The command line.**

```sh
cargo install rustx-cli --force
```

The pages are compiled by `#[rustx::main]`, from the library your project
depends on. The command line starts cargo and stamps the executable, and does not
compile pages. The two can differ in version without the build failing, but keep
them together so `rustx --help` describes what you run.

**The editor.** Install the language server again, and the extension if there is
a newer one. See [the editor](/docs/tooling/the-editor).

```sh
cargo install rustx-lsp --force
```

Restart the language server from the command palette afterwards. A running
server holds its own file, and an old one underlines errors the compiler does not
report.

## When you build the first time

- Close every window of the application, and any `rustx dev` that is still
  running. They hold the executable, and the build says which file is held.
- The engine is the system's web view: there is nothing to fetch, and an
  upgrade does not change the browser the application runs in.
- Rust 1.88 or later is required.

## From 0.4 to 0.5

0.5 changes the engine and the installer, so read this before you build.

- **The engine is the system's web view.** The Chromium Embedded Framework is
  gone. Delete anything of yours that named `libcef` or an engine folder beside
  the executable. What a page can decode or draw is what WebView2, WKWebView or
  WebKitGTK can: test the media you rely on.
- **The application installs itself.** `rustx package` no longer writes a
  separate setup program; the stamped binary shows the install wizard when it
  is run outside its install folder. Add `Config::portable()` to opt out, and
  see [packaging](/docs/tooling/packaging) for the `system/` screens you can
  write.
- **Every window has Inter and a default theme**, in a CSS layer: a rule of
  yours wins. If you relied on the browser's default font, say so in your
  stylesheet. See [fonts and theme](/docs/getting-started/fonts-and-theme).
- **`Config::version`, `description` and `publisher`** default to `Cargo.toml`.
- **The not-found text** is now "This page could not be found."

## The changelog

[`CHANGELOG.md`](https://github.com/AZTRA2022/rustx/blob/main/CHANGELOG.md) at the
root of the repository lists what changed in each release, and the editor
extension has its own. Besides that:

- the git history of the repository. A commit message says what changed
  and why, at length;
- [what's left](/docs/whats-left), which says what is still missing and
  what has closed;
- the rustdoc of the crate you use, for signatures.

If an upgrade breaks your build, the compiler errors usually name the function
that moved. When they do not, an issue is welcome. See
[contributing](/docs/tooling/contributing).

## Deprecation and support

No deprecation policy and no support window are written down. Pin the version
you ship with, and move when you choose to.
