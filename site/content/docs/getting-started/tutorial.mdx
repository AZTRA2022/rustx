title: "Tutorial: a notes app"
description: "Build a small notes editor with a page, shared state, file dialogs, two routes and a release build."
---

This builds a notes editor in about half an hour: a text area, a word count,
Open and Save buttons that use the system's dialogs, an About screen, and a
release build with its own name, version and icon.

You need what [installation](/docs/getting-started/installation) installs, and
a terminal.

## 1. The project

```sh
rustx new notes
cd notes
rustx dev
```

A window opens with a counter. Leave `rustx dev` running: it rebuilds when you
save a file, and the window comes back. A `let mut` at the top of a page
survives the relaunch. See [the commands](/docs/tooling/the-commands).

## 2. A text area

Replace `app/page.rsx`:

```rust
// app/page.rsx
let mut text = String::new();

fn Page() -> Element {
    let words = text.split_whitespace().count();

    return <main style={{
        display: "grid",
        gridTemplateRows: "1fr auto",
        height: "100vh",
        gap: "8px",
        padding: "16px",
        boxSizing: "border-box",
        fontFamily: "system-ui, sans-serif",
    }}>
        <textarea
            style={{ resize: "none", padding: "12px", fontSize: "16px" }}
            placeholder="Write something…"
            value={text.clone()}
            onInput={move |event| text = event.value}
        />
        <small>{words} words</small>
    </main>;
}
```

Type in it. `let mut text` at the top of the file is **shared state**. Writing it
from `onInput` redraws the page on the next frame, and nothing else is needed.
There is no Tailwind in this project yet, so the `style` object does the work.
See [state](/docs/getting-started/state) and
[attributes and events](/docs/getting-started/attributes-and-events).

## 3. Move the logic out of the page

Counting words is a rule, and a rule is worth a test. Make `src/stats.rs`:

```rust
// src/stats.rs
pub fn words(text: &str) -> usize {
    text.split_whitespace().count()
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn words_are_separated_by_any_whitespace() {
        assert_eq!(words("one  two\nthree"), 3);
        assert_eq!(words("   "), 0);
    }
}
```

Declare it in `src/main.rs` with `mod stats;`, and use it in the page:

```rust
let words = stats::words(&text);
```

The public functions of the application's modules are in scope in the pages.
Run `cargo test` to check the rule. See [testing](/docs/tooling/testing).

## 4. Open and save

Add three states and a row of buttons. The page becomes:

```rust
// app/page.rsx
let mut text = String::new();
let mut path = String::new();
let mut dirty = false;
let mut status = String::new();

fn Page() -> Element {
    let words = stats::words(&text);
    let name = if path.is_empty() { "Untitled".to_string() } else { path.clone() };

    return <main style={{
        display: "grid",
        gridTemplateRows: "auto 1fr auto",
        height: "100vh",
        gap: "8px",
        padding: "16px",
        boxSizing: "border-box",
        fontFamily: "system-ui, sans-serif",
    }}>
        <div style={{ display: "flex", gap: "8px", alignItems: "center" }}>
            <button onClick={move |_| {
                let ask = rustx::dialog::Ask::new("Open a note").filter("Text", ["txt", "md"]);
                let Ok(files) = rustx::dialog::open(ask) else { return; };
                let Some(chosen) = files.into_iter().next() else { return; };
                match std::fs::read_to_string(&chosen) {
                    Ok(read) => {
                        text = read;
                        path = chosen.display().to_string();
                        dirty = false;
                        status = String::new();
                    }
                    Err(why) => status = format!("Could not read {}: {why}", chosen.display()),
                }
            }}>Open…</button>

            <button onClick={move |_| {
                let ask = rustx::dialog::Ask::new("Save the note").named("note.txt");
                let Ok(target) = rustx::dialog::save(ask) else { return; };
                match std::fs::write(&target, &text) {
                    Ok(()) => {
                        path = target.display().to_string();
                        dirty = false;
                        status = String::new();
                    }
                    Err(why) => status = format!("Could not write {}: {why}", target.display()),
                }
            }}>Save as…</button>

            <span>{name}{if dirty { " •" } else { "" }}</span>
        </div>

        <textarea
            style={{ resize: "none", padding: "12px", fontSize: "16px" }}
            value={text.clone()}
            onInput={move |event| { text = event.value; dirty = true; }}
        />

        <small>{words} words {status.clone()}</small>
    </main>;
}
```

Three things to see here:

- Cancelling a dialog is `Err`, a normal case, so the handlers `return` quietly.
  See [file dialogs](/docs/the-system/file-dialogs).
- Reading and writing a small file in a handler is fine. The dialog runs its own
  message loop, so the window does not look frozen while it is open.
- A failure is a **value**: `status` holds the message and the page draws it. No
  panic is involved. See [error handling](/docs/getting-started/error-handling).

## 5. A second screen

Routes are folders. Make `app/about/page.rsx`:

```rust
// app/about/page.rsx
fn Page() -> Element {
    let about = rustx::window::about();

    return <main style={{ padding: "16px", fontFamily: "system-ui, sans-serif" }}>
        <h1>{about.name.clone()}</h1>
        <p>Version {about.version.clone()}</p>
        <p>{about.description.clone()}</p>
        <button onClick={move |_| { rustx::router::back(); }}>Back</button>
    </main>;
}
```

And a button to it in `app/page.rsx`, next to the others:

```rust
<button onClick={move |_| rustx::router::navigate("/about")}>About</button>
```

Use a button with `navigate`, not an `<a href>`: a link would navigate the
document, and the engine refuses anything but the application's own file. See
[navigating](/docs/the-router/navigating) and
[security](/docs/the-system/security).

The note is still there when you come back, because a top-of-file `let mut`
belongs to the application and not to the screen.

## 6. A name, a version and an icon

Put a real `.ico` file at `assets/icon.ico`, and replace `src/main.rs`:

```rust
// src/main.rs
mod stats;

use rustx::{App, Config};

#[rustx::main]
fn main() -> Result<(), rustx::Error> {
    let app = App::new(
        Config::new("Notes")
            .size(900, 640)
            .version(env!("CARGO_PKG_VERSION"))
            .description("A small notes editor")
            .publisher("You"),
    )?;

    app.run()
}
```

`assets/icon.ico` is found without being declared. `.version(…)` is what the
About screen shows. See [the window](/docs/the-window) and
[configuration](/docs/tooling/configuration).

## 7. Build it

Close the window and stop `rustx dev`. A running window holds the engine's
library, and the build would fail.

```sh
rustx build --release
```

`target/release/notes.exe` now carries the name "Notes", the version from
`Cargo.toml` and your icon. Run it:

```sh
target\release\notes.exe
```

To give it to someone, you need more than the `.exe`: the engine's files sit
beside it, and there is no installer. Read [packaging](/docs/tooling/packaging)
before you do. It lists what to copy and what to test first.
