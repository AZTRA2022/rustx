Components are written in `.rsx` files — the syntax of JSX,
the language of Rust — and a `let mut` there is a state, with no annotation, no
macro, no `store::`. npm libraries (React, Recharts, Tailwind,
shadcn) are used from the `.rsx` itself. The `main.rs` of a project
is four lines, because the ceremony is the framework's job.

Rust and React live in **the same process**: an `onClick` is a
function call, not a serialized message, and props cross the boundary
as V8 values.

<Callout title="Status">
Windows is written and measured. macOS and Linux compile and refuse by
naming the file they are missing. The version is `0.2.0`: the API may
still change.
</Callout>

## What it looks like

```rust title="app/counter/page.rsx"
let mut order = vec!["a".to_string(), "b".to_string(), "c".to_string()];

fn Page() -> Element {
    return <div>
        <div id="first">{Counter()}</div>
        <div id="second">{Counter()}</div>

        <ul id="rows">
            {order.iter().map(|key| <li key={key.clone()}>{Counter()}</li>).collect::<Vec<_>>()}
        </ul>

        <button id="rotate" onClick={move |_| order.rotate_right(1)}>rotate</button>
    </div>;
}

/// One `let mut n = 0;`, as many counters as there are places it is
/// written — and as many as there are keys in a list.
fn Counter() -> Element {
    let mut n = 0;
    return <button onClick={move |_| n += 1}>{n}</button>;
}
```

This file is `apps/counter/app/counter/page.rsx`, as it is. There is no
`useState`, no provider, no reducer: `let mut n = 0;` written
once gives as many counters as there are places it is called, and
the rows of the list each keep their own through a rotation.
