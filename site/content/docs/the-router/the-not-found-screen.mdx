The defaults are Next.js's own pages, with the same markup, colours (black on white, white on black
by the system's preference) and system font stack: `404 | This page could not be found.`, and for a page
that fell over `Application error: an exception has occurred…` with what the panic said under it.
Every window starts with Inter (variable; latin, latin-ext, cyrillic, greek and vietnamese subsets, SIL OFL, carried in the binary) as the
font of `html`, and with the colours as CSS variables: `--rx-bg`, `--rx-fg`, `--rx-muted`, `--rx-border`,
`--rx-accent`, `--rx-danger`, black on white or white on black by the system's preference. The seven
`system/` screens use them, so a page of your own that does too looks the same. A page that names its own
font on `body` keeps it. `rustx::screens::{not_found, forbidden, unauthorized, error_screen}` give the same
screens as elements to put in a layout (`403 | You are not allowed to see this page.`, `401 | You must be
signed in to see this page.`).

`Config` says where it starts, and what is shown for a route that
nobody declared.

```rust
Config::new("My app")
    .start("/settings")          // `/` by default
    .not_found(NotFound)         // otherwise: "This page could not be found."
```

## The screen itself

`not_found` takes a `fn() -> Element`. It lives next to the window, so
in `src/main.rs` and not in `app/`: it is not a `.rsx` file, and tags are a
privilege of the `app/` folder.

```rust
use rustx::{AttributeValue, Element, Handler};

#[allow(non_snake_case)]
fn NotFound() -> Element {
    Element::tag("main")
        .attribute("class", AttributeValue::Text("p-10".to_string()))
        .child(
            Element::tag("h1")
                .child(Element::Text("This route does not exist".to_string()))
                .build(),
        )
        .child(
            Element::tag("p")
                .child(Element::Text(format!("asked for: {}", rustx::router::current())))
                .build(),
        )
        .child(
            Element::tag("button")
                .handler("onClick", Handler::new(|_| rustx::router::navigate("/")))
                .child(Element::Text("home".to_string()))
                .build(),
        )
        .build()
}
```

`rustx::router::current()` says what was asked for: a not-found screen
that does not say it leaves the user with nothing to report.

## If you want it written in tags

Then it is a route like the others, and `not_found` shows it:

```text
app/not-found/page.rsx
```

```rust
Config::new("My app").not_found(|| {
    rustx::router::navigate("/not-found");
    Element::Empty
})
```

This is more machinery for the same result; the `Element` builder is there for
this specific case.

## `start`

The opening screen. `/` by default, and `start("/settings")` for an
application whose first thing to do is a setting.

A second window, however, opens on the route it is given —
`What::new("tool").at("/tool")` — and not on `start`. See
[several windows](/docs/the-window/several-windows).

<Callout type="warn" title="This page could not be found.">
This is the default screen of `not_found`. When it appears without having been wanted: check the path passed to `navigate`, the name of the folder in
`app/`, and the `.start(…)` of `Config`.
</Callout>

The base rules are in `@layer rustx-base`, so any rule your application writes, in any order, wins over
them. `RUSTX_THEME=light` or `dark` forces a theme to look at it. A frameless window gets a bar to drag
and the three marks on every screen the framework draws (`rustx::window::is_frameless()` tells a page of
your own whether to draw them).
