Routes are the `app/` folder. There is no table to write and no
`<Route>` to declare: a `page.rsx` file **is** a route, and its
path inside `app/` is its URL.

```text
app/page.rsx                      →  /
app/settings/page.rsx             →  /settings
app/device/[id]/page.rsx          →  /device/<something>
app/files/[...path]/page.rsx      →  /files/<everything else>
app/help/[[...path]]/page.rsx     →  /help, and /help/<everything else>
app/(shop)/cart/page.rsx          →  /cart  (the group is not in the URL)
app/layout.rsx                    →  a frame around what is below it
app/repos/loading.rsx             →  what is shown while the page has nothing yet
app/repos/error.rsx               →  what is shown if the page fails
```

## On one page

```rust
// app/repos/[owner]/[name]/page.rsx
fn Page(owner: String, name: String) -> Element {
    let tab = rustx::router::query("tab");

    return <section>
        <h1>{owner}/{name}</h1>
        <nav>
            <button onClick={move |_| {
                rustx::router::navigate(rustx::router::with_query("tab", Some("issues")));
            }}>issues</button>
            <button disabled={!rustx::router::can_go_back()}
                onClick={move |_| { rustx::router::back(); }}>back</button>
        </nav>
        {if tab == "issues" { Issues() } else { Readme() }}
    </section>;
}
```

<Callout title="What differs from Next.js">
There is no server rendering, so no `generateStaticParams`, no cached
`fetch`, no `revalidate`: a desktop application draws what it has at hand. Everything else — the folders, the brackets, the groups, the layouts, `loading`, `error`, the precedence of routes, the history — reads the same as there.
</Callout>
